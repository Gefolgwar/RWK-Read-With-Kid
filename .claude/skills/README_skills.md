# AI Agent Workflow Map (Matt Pocock Skills v1.1)

Цей документ описує покроковий процес та інженерний цикл розробки програмного забезпечення за допомогою AI-агентів та набору скілів Метта Покока (`mattpocock/skills`).

---

## 🗺️ Загальна схема процесів (Workflow Diagram)

```text
[Крок 0: Ініціалізація та налаштування]
      │
      ▼
   /setup-matt-pocock-skills ── (налаштування Issue Tracker, міток, шляхів до docs)
      │
      ▼
[Крок 1: Дослідження та формування ідеї (Pre-Spec)]
   ├── 💡 Великий / туманний проєкт? ──> /wayfinder
   │                                           │
   │                                           ├──> /research (фоновий пошук/документація)
   │                                           ├──> /prototype (швидкий прототип UI чи логіки)
   │                                           └──> /grill-with-docs (інтерв'ю + глосарій CONTEXT.md + ADR)
   │
   └── 🎯 Невеликий / зрозумілий фіча-сет? ──> /grill-with-docs (або /grill-me)
      │
      ▼
[Крок 2: Фіксація специфікації]
   /to-spec ── (синтезує всі рішення з діалогів у підсумкову специфікацію)
      │
      ▼
[Крок 3: Декомпозиція на тикети]
   /to-tickets ── (розбиває Spec на атомарні тикети з залежностями)
      │
      ▼
[Крок 4: Цикл кодингу (для кожного окремого тикету)]
   ┌────────────────────────────────────────────────────────────────────────┐
   │ /implement                                                             │
   │   ├── /tdd ────────────── (написання тесту [Red] ➔ реалізація [Green])│
   │   ├── /diagnosing-bugs ── (якщо щось зламалося або падають тести)       │
   │   └── /code-review ────── (субагенти: перевірка специфікації,          │
   │                            стандартів проєкту та Fowler code smells)   │
   │        └── Git Commit ─── (фіксація виконаного тикету)                  │
   └────────────────────────────────────────────────────────────────────────┘
      │ (повторювати для всіх тикетів)
      ▼
[Крок 5: Довгострокова підтримка архітектури]
   /improve-codebase-architecture ── (періодичний аналіз коду на спрощення та усунення складностей)
```

## 📋 Покроковий опис етапів

### Крок 0: Ініціалізація та налаштування проєкта

- **`npx skills@latest add mattpocock/skills`** — завантаження та оновлення інструкцій скілів.
- **`/setup-matt-pocock-skills`** — первинна конфігурація проєкту:
  - Вибір трекера задач (GitHub Issues, Linear або локальні Markdown-файли).
  - Налаштування міток (labels) для сортування та триажування тикетів.
  - Визначення папки для збереження документації (наприклад, `.agents/`).

---

### Крок 1: Дослідження та формування ідеї (Pre-Spec Phase)

На цьому етапі ви усуваєте невизначеність і синхронізуєте бачення з AI-агентом перед написанням коду.

#### Варіант А: Великий, складний або туманний проєкт

- **`/wayfinder`** — розбиває велику ідею на карту дослідницьких тикетів із визначенням залежностей та блокувань.
  - **`/research`** — запускає фонового агента для вивчення документації, бібліотек чи першоджерел без блокування основного чату.
  - **`/prototype`** — створює швидкий, одноразовий прототип (UI або логіки) для тестування гіпотез.
  - **`/grill-with-docs`** — проводить серію виснажливих запитань (по одному за раз), фіксує глосарій домену у `CONTEXT.md` та створює записи архітектурних рішень (ADR).

#### Варіант Б: Зрозуміла або невелика фіча

- **`/grill-with-docs`** (або **`/grill-me`**) — коротке інтерв'ю для уточнення крайових випадків та узгодження вимог.

---

### Крок 2: Фіксація специфікації

- **`/to-spec`** _(раніше `/to-prd`)_ — автоматично синтезує весь діалог, результати досліджень та прототипів у єдиний чіткий документ специфікації (`Spec`).
  - Не ставить нових запитань, а збирає вже прийняті рішення.

---

### Крок 3: Декомпозиція на тикети

- **`/to-tickets`** _(раніше `/to-issues`)_ — бере специфікацію та декомпозує її на атомарні тикети.
  - Кожен тикет розрахований на **одну окрему сесію AI-агента**.
  - Чітко визначаються зв'язки між тикетами (що кого блокує).

---

### Крок 4: Цикл розробки (Coding Loop)

Для кожного тикету відкривається нова сесія агента та запускається цикл реалізації.

1. **`/implement`** — головний скіл реалізації задач.
2. **`/tdd`** — розробка через тестування за принципом **Red ➔ Green**:
   - Написання тесту, який падає (**Red**).
   - Написання мінімального коду для проходження тесту (**Green**).
3. **`/diagnosing-bugs`** — дисциплінований цикл діагностики та виправлення помилок у разі збоїв.
4. **`/code-review`** — автоматична перевірка коду послідовно по двох осях:
   - **Standards**: перевірка за `coding-standards.md` та усунення "запахів коду" (Martin Fowler Code Smells).
   - **Spec**: перевірка відповідності коду початковому тикету та специфікації.
5. **Git Commit** — фіксація змін у поточній гілці після успішного рев'ю.

---

### Крок 5: Довгострокова підтримка архітектури

- **`/improve-codebase-architecture`** — періодичний запуск (раз на декілька днів) для виявлення складностей у кодовій базі, поглиблення модулів та запобігання перетворенню проєкту на "грудку бруду" (Ball of Mud).
